# 推播呈現格式

> 目錄：../CLAUDE.md

## 什麼時候用
- 每日推播呈現給使用者時（`--dry` 預檢通過之後）。

## 主領域／跨域／金融：每篇固定四段
1. **① 問題背景**：這個領域原本卡在什麼問題？為何重要？痛點的**機制成因**（為什麼會這樣，不是症狀）。要講到讓人有感、有畫面——這是每篇的賣點。
2. **② 核心發想**：關鍵 insight／類比／視角是什麼？**為什麼這個想法能解掉 ①**（講因果，不只列做法）。
3. **③ 技術細節**：實際怎麼做（公式／演算法／關鍵設計與代價）。跨域／金融這段必須明確**回接主領域機制（anchor）**。
4. **④ 為何重要／影響了什麼**：換掉了什麼舊想法或共識？往下解鎖或啟發了什麼？這是典範轉移論文的頭條，不可一句帶過。寫不出 ④ → 多半是工程微調，回 `paper_selection.md` 換片。

末尾一行：推薦理由（關聯記憶脈絡或昨日進度；複習須明講「上次卡在 X 機制」）＋ ﹝想法軸或借用領域﹞標籤。

## 問題優先原則
- 數學／公式只是解問題的工具，不是賣點。不要一開頭就鋪數學，不要以「數學很漂亮」當推薦理由。
- 公式只放在 ②③，且每個符號都要說它在解 ① 的哪一塊。能用白話或類比講清楚就用白話。
- 不可用「把 ooo 改成 xxx」式的結論句帶過。

## wild 軌
- 標題＋連結 ／ 一句話為什麼有趣 ／ ﹝領域﹞標籤（見 `wild_track.md`）。

## 結尾固定三行
- 「有興趣的論文？回覆 `teaser <paper_id>`」
- 「想直接深入？回覆 `deep <paper_id>`」
- 「今天沒空就略過，明天照常推播。」

## 禁止
- 推播裡不放考題。
- 不主動顯示「連續 N 天」（見 `streak.md`）。

## 驗收標準
- 讀者看完 ①② 能回答「問題是什麼、為何這招管用」；看完 ④ 能回答「這篇憑什麼重要」。
- 讀者若只記得「有一堆公式」而答不出原本的問題 → 這篇寫失敗。

## 存放位置
- 呈現內容只在對話裡；不寫檔（紀錄由 `push_log` 負責）。
