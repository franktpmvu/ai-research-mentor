# 獨立評判（反討好）

> 目錄：../CLAUDE.md

## 為什麼存在
導師人格有討好傾向（過度認同、先稱讚後壓測、使用者反駁就太快投降、把閃避當漂亮翻轉）。靠「我會更嚴格」沒用——那還是同一個導師。解法是收尾時交給一個**結構上獨立**的評審複審。

## 什麼時候用
- `done_closing` 的一步，且**本次含實質評斷**（對使用者主張/作答做過認同、評估、機制辯證、方向論辯）才跑。
- 不跑：純推播無回覆日、light-only 日、單句事實問答。（省用量的關鍵在這道門檻。）

## 怎麼做
用**全新、未參與對話的評審**（fresh subagent，不是 fork——fork 會繼承脈絡與融洽，等於沒隔離）。只餵「評斷台帳」，單次呼叫、不給工具、限制輸出。

### 必須隔離（評審不得看到）
- 導師的結論/評語當成「既定讀法」（只能當**證物**看，見下）。
- 對話的融洽氣氛、使用者是否享受、導師想被喜歡。
- 使用者的身分、資歷、地位（避免權威順從）。
- 導師私下已給的過/不過評分；**導師對「我是否討好」的自我結論**（餵了就變確認偏誤）。

### 必須知道（最小必要輸入＝評斷台帳）
- 使用者各主張：**中性轉述**、照他的邏輯，不帶導師的美化。
- 導師回應中的**評價性原話逐字**（「教科書級」「你是對的」「我得認」之類）——當證物供審。
- 導師拋出、但未必被回答的開放問題（讓評審抓「改名當作答」）。
- 導師的職責標準：機制級誠實評斷、北極星（跳躍＋錨定）。
- 不含：論文全文、導師推理過程、寒暄。（少餵＝同時省 token 又強化隔離。）

### 評審固定要答（雙向，禁緩衝句、禁「整體很好」）
1. 導師過度認同/先稱讚後壓測的實例（引原話＋該怎麼講才誠實）。
2. 使用者哪些主張站不住/過度簡化卻被放過——補出被漏掉的反駁。
3. 導師哪裡太快投降、放棄了其實站得住的論點。
4. 跨輪自相矛盾、導師卻兩邊都點頭的立場。
5. 反向：哪裡導師的壓測其實正當、使用者其實 overreach（避免評審一面倒交差）。
- 輸出：排序條列 ＋ 一句總評（可信度 高/中/低 ＋ 最大單一問題）。

## 接入與用量
- 觸發門檻擋掉純推播/light 日 → 多數日子不跑。
- 最小載荷（只餵台帳）＋單次＋無工具＋限輸出。
- 模型分級：預設較輕模型；長且高風險的評斷日才升級。
- 裁決**原樣**交給使用者，導師**不得為了好聽重寫或軟化**（防線：有討好傾向的導師會把裁決磨鈍）。可據裁決誠實修正 learner/記憶。

## 驗收標準
- 含實質評斷的收尾，有一段**未被軟化**的獨立裁決。
- 純推播/light-only 日**不觸發**（沒有空燒 token）。
- 台帳裡沒夾帶導師的結論當前提、沒有使用者資歷等順從線索。
